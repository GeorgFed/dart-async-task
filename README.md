# Dart: Future, Stream и сетевой репозиторий

Практика на 80 минут. Реализуйте две небольшие модели и `HttpCoinRepository`, который выполняет контракт `CoinRepository`. Для **2 баллов** обязательны загрузка данных, последовательный Stream, поллинг и преобразование потока.

## Запуск

Нужен **Dart 3.9+**. Если Flutter уже установлен, используйте входящий в него Dart. Иначе установите [Dart SDK](https://dart.dev/get-dart). Откройте папку проекта в VS Code с расширением Dart или в другом редакторе.

```bash
dart --version
dart pub get
dart test
dart run task.dart
```

Перед реализацией тесты падают на `UnimplementedError`: это ожидаемо. Основной запуск и все тесты используют **моки**, не обращаются к CoinGecko и не требуют ключа. Интернет нужен для первоначальной установки SDK и зависимостей.

Меняйте `lib/coin_api.dart`. Готовые сетевой помощник, учебный клиент и методы вывода в `bin/main.dart` переписывать не нужно. Тесты не менять и не ослаблять.

## Модели: всего шесть полей

| Модель | Поле Dart | Поле JSON |
|---|---|---|
| `Coin` | `id: String` | `id` |
| `Coin` | `name: String` | `name` |
| `Coin` | `priceUsd: double?` | `current_price` |
| `CoinDetails` | `name: String` | `name` |
| `CoinDetails` | `description: String` | `description.en` |
| `CoinDetails` | `changePercent: double?` | `market_data.price_change_percentage_24h` |

В `fromJson` только извлеките эти значения. Числа могут быть `int` или `double`: используйте `num` и `toDouble()`. Отсутствующая цена или процент становятся `null`, отсутствующее описание — `''`. Для обязательных имени/id можно считать, что API передаёт строки: отдельный валидатор схемы не нужен.

Список:

```json
[{"id":"bitcoin","name":"Bitcoin","current_price":65000}]
```

Детали:

```json
{"name":"Bitcoin","description":{"en":"Digital money"},"market_data":{"price_change_percentage_24h":2.5}}
```

## Реализуйте весь класс HttpCoinRepository

Конструктор и сетевой помощник `_api` уже готовы. `_api.get(path, query)` возвращает декодированный JSON; он сам обрабатывает HTTP status, повреждённый JSON, ошибку подключения и таймаут. Пути указываются относительно `/api/v3/`.

| Метод | Контракт |
|---|---|
| `getTopCoins(limit)` | `/coins/markets`: `vs_currency=usd`, `order=market_cap_desc`, `per_page=limit`, `page=1`. При limit вне 1–250 — `ArgumentError` до запроса. Вернуть `List<Coin>`; если верхний JSON не список — `CoinApiException`. |
| `getCoinDetails(id)` | `/coins/{id}` с `localization=false`. Вернуть `CoinDetails`; если верхний JSON не объект — `CoinApiException`. |
| `getCoinsStream(ids)` | Через `async*` и `yield` загружать детали последовательно, в порядке id. Пустой список завершается без запросов. Первая ошибка завершает поток; следующие id не загружаются. |
| `pollPrices(ids, interval)` | `/coins/markets` с `vs_currency=usd`, `ids` через запятую и `per_page=250`. Первый запрос сразу после подписки. После ответа и отправки события выдержать `interval`, затем повторить. Запросы не перекрываются. `interval <= 0` — `ArgumentError`; пустой список — завершение без запросов. Ошибка завершает поток. Отмена прекращает новые запросы. |
| `getGrowingCoinNames(ids)` | Преобразовать `getCoinsStream`: `where` оставляет только `changePercent > 0`, `map` извлекает имя. `null`, ноль и отрицательные проценты пропускаются. Сохраняются порядок и ошибки. |
| `close()` | Закрыть `_api` после завершения работы. |

Для поллинга достаточно цикла в `async*`: запрос → `yield` → `Future.delayed`. `take(2)` в готовом CLI ограничивает его двумя обновлениями. Отмена потока не обязана прерывать уже начатый HTTP-запрос или текущую паузу, но новые запросы после отмены не выполняются. В этой практике поддерживаем до 250 id в одном polling-запросе.

В `main` все демонстрации уже включены, каждая вынесена в отдельный метод ниже `main`. CLI использует интерфейс, а HTTP-клиент закрывается в `finally`.

## Проверка и баллы

```bash
dart analyze
dart test
dart run task.dart
```

- **0 баллов:** основная загрузка данных не реализована или решение не удаётся объяснить.
- **1 балл:** обе модели, список, детали и последовательный поток работают; проходят группы «Модели», «Запросы» и «Stream»; студент объясняет `await` и `yield`.
- **2 балла:** также работают поллинг и `where`/`map`, проходят все тесты и весь CLI; студент объясняет порядок событий, остановку поллинга и закрытие клиента.

Сдать код, вывод проверок и короткое объяснение. Зелёные тесты без объяснения не заменяют понимание. Критерии объявляются до начала работы; к прошлым сдачам не применяются.

## Настоящий API — дополнительная проверка

```bash
dart run task.dart --live
```

Режим выполняет реальные запросы, поэтому возможны HTTP 429, недоступность сети и пауза 30 секунд между обновлениями. Успех реального API не влияет на оценку. При необходимости задайте личный Demo key через переменную окружения `COINGECKO_DEMO_API_KEY`; не добавляйте ключ в код или Git.

Документация: [Demo API key](https://docs.coingecko.com/docs/setting-up-your-api-key), [список](https://docs.coingecko.com/v3.0.1/reference/coins-markets), [детали](https://docs.coingecko.com/v3.0.1/reference/coins-id).

## Опционально, без дополнительных баллов

- Сделать альтернативный `DioCoinRepository` за тем же `CoinRepository`, сохранив основной вариант и добавив тесты с моками для Dio.
- Подключить `json_serializable` и `build_runner`, получить рабочую генерацию этих же моделей и объяснить разбор вложенных полей. Сохранить шесть полей и тот же контракт.

Для обязательной части Dio и кодген не нужны.
